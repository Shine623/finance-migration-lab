# 财务系统数据库迁移 需求规格说明书

| 项 | 内容 |
|---|---|
| 项目名称 | 集团财务系统数据库迁移 |
| 文档版本 | v1.0 |
| 编制日期 | 2025-04 |
| 需求方 | 集团财务部 |
| 实施方 | 信息部 |

## 一、背景与目标

### 1.1 背景

集团财务系统当前运行在 Oracle 19c 上，存在两个问题：

1. **成本高**：Oracle License 每年约 30 万，且按 CPU 核数计费，扩容成本陡增
2. **运维复杂**：DBA 只有 1 人，Oracle 的日常维护（RMAN 备份、DataGuard 同步、AWR 报告）负担重

集团已决定技术栈统一向 MySQL 收敛，财务系统是最后一个迁移的核心系统。

### 1.2 目标

| 指标 | 现状 | 目标 |
|---|---|---|
| 数据库 | Oracle 19c | MySQL 8.0 |
| License 成本 | 30 万/年 | 0（社区版） |
| 数据量 | 240 万行 | 全量迁移 |
| 停机时间 | - | ≤ 4 小时 |
| 数据一致性 | - | 100%（三级校验全过） |
| 核心查询性能 | 基准 | 不超过原 1.2 倍 |

## 二、需求清单

### 2.1 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| F-01 | 全量迁移 6 张主表 | P0 | 行数完全一致 |
| F-02 | 支持增量追平 | P0 | binlog 应用到最终位置 |
| F-03 | 三级一致性校验 | P0 | L1/L2/L3 全过 |
| F-04 | 支持快速回滚 | P0 | 30 分钟内完成 |
| F-05 | 迁移过程可追溯 | P1 | 每步有日志与签字 |

### 2.2 数据需求

| 表名 | 行数（估） | 说明 |
|---|---|---|
| ACCOUNT_SUBJECT | 1,200 | 会计科目，层级结构 |
| VOUCHER | 1,850,000 | 凭证，最大的表 |
| BALANCE | 96,000 | 科目余额，按期间 |
| PARTNER | 8,500 | 往来单位 |
| DEPARTMENT | 320 | 部门 |
| CURRENCY | 12 | 币种 |

### 2.3 不迁移的内容

| 项 | 原因 | 后续方案 |
|---|---|---|
| 2015 年前的历史数据（约 600 万行） | 已归档，极少查询 | 单独迁移到历史库 |
| 存储过程（12 个） | MySQL 语法差异大 | 改为应用层实现 |
| 触发器（5 个） | 同上 | 改为应用层实现 |
| 物化视图（3 个） | MySQL 无对应特性 | 改为定时任务 + 汇总表 |

## 三、字段映射需求

### 3.1 类型映射规则

| Oracle 类型 | MySQL 类型 | 说明 |
|---|---|---|
| NUMBER(18,4) | DECIMAL(18,4) | **精度必须一致**，否则截断 |
| NUMBER(10) | BIGINT | |
| VARCHAR2(64) | VARCHAR(64) | 字符集 utf8mb4 |
| DATE | DATETIME | 统一存 UTC |
| CHAR(1) 'Y'/'N' | TINYINT(1) 1/0 | 布尔值转换 |
| CLOB | LONGTEXT | |
| SEQUENCE | AUTO_INCREMENT | 导入后重置 |

### 3.2 特殊处理

| 场景 | 处理方式 |
|---|---|
| Oracle 空串 `''` | 视为 NULL（Oracle 本身就这样处理），迁移时统一转 NULL |
| 日期时区 | 存 UTC，应用层按 Asia/Shanghai 展示 |
| 中文编码 | 导出时 `NLS_LANG=AL32UTF8` |
| 自增主键 | 导入后 `ALTER TABLE ... AUTO_INCREMENT = max(id)+1` |

## 四、非功能需求

### 4.1 性能

| 场景 | 要求 |
|---|---|
| 全量导入 | ≤ 90 分钟 |
| 增量追平 | ≤ 15 分钟 |
| 三级校验 | ≤ 25 分钟 |
| 割接总耗时 | ≤ 240 分钟 |
| 核心查询（按期间查余额） | ≤ Oracle 的 1.2 倍 |

### 4.2 可用性

- 割接窗口：周六 00:00 - 04:00（业务低峰）
- 回滚时间：≤ 30 分钟
- 数据零丢失

### 4.3 安全

- 数据库账号最小权限
- 迁移过程中导出的文件加密存储，迁移完成后删除
- 操作日志保留 1 年

## 五、验收标准

| 项 | 标准 | 验收方式 |
|---|---|---|
| 数据完整性 | 6 张表行数完全一致 | L1 校验 |
| 数据准确性 | 关键字段 checksum 一致 | L2 校验 |
| 数据精确性 | 抽样 200 条逐字段一致 | L3 校验 |
| 应用功能 | 冒烟测试 5 个用例全过 | 功能测试 |
| 性能 | 核心查询 ≤ Oracle 1.2 倍 | 压测 |
| 观察期 | 切换后 7 天无 P0/P1 故障 | 监控 |

## 六、约束与假设

### 约束

1. 割接窗口不可延长（业务方只批准 4 小时）
2. 迁移期间业务系统只读
3. 现有应用代码不能大改（只允许改连接配置）

### 假设

1. Oracle 与 MySQL 服务器在同一内网，网络带宽 ≥ 1Gbps
2. 有可用的测试环境做演练
3. 业务方能配合在窗口内待命

## 七、风险登记

| 编号 | 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|---|
| R-01 | 数据不一致 | 中 | 高 | 三级校验，任一不过即停止 |
| R-02 | 割接超时 | 中 | 中 | 预留 1 小时缓冲 |
| R-03 | 应用兼容性问题 | 中 | 高 | 提前做兼容性测试 |
| R-04 | 性能不达预期 | 低 | 中 | 提前压测，准备索引方案 |
| R-05 | 回滚失败 | 低 | 高 | 回滚脚本必须演练过 |
