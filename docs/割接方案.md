# 财务系统割接方案

> 本文档是割接窗口内的**操作手册**，每一步都要有人确认签字。
> 演练结果：全流程 186 分钟，计划 240 分钟。

- [ ] 源库 binlog 已开启，格式为 ROW
- [ ] MySQL 主从状态正常
- [ ] 应用连接串切换脚本已准备
- [ ] 回滚脚本已演练通过
- [ ] 相关人员到位
- [ ] 业务方已通知用户
- [ ] 监控告警已配置
- [ ] 磁盘空间充足（≥ 50G）

## 详细步骤

### 步骤 1：停止写入（00:00）

```bash
curl -X POST http://app-server:8080/admin/maintenance -d "enable=true"
mysql -uroot -p -e "SHOW PROCESSLIST;"
```

**确认人**：运维
**失败处理**：若有长事务，`KILL` 后重试

---

### 步骤 2：记录最终 binlog 位置（00:05）

```bash
mysql -uroot -p -e "FLUSH LOGS; SHOW MASTER STATUS\G" | tee export/final_binlog_pos.txt
```

**确认人**：DBA

---

### 步骤 3：增量追平（00:07）

```bash
mysqlbinlog --start-position=<预迁移pos> \
            --stop-position=<最终pos> \
            mysql-bin.0000XX | mysql -h target -uroot -p finance
```

**确认人**：DBA
**失败处理**：检查 binlog 格式是否为 ROW；必要时重做全量

---

### 步骤 4-6：三级校验（00:22 - 00:45）

```bash
python3 scripts/04_verify.py --level L1
python3 scripts/04_verify.py --level L2
python3 scripts/04_verify.py --level all
```

**通过标准**：全部 PASS
**确认人**：开发
**失败处理**：**立即停止，执行回滚**

---

### 步骤 7：切换应用连接（00:45）

```bash
sed -i 's|jdbc:oracle.*|jdbc:mysql://mysql-master:3306/finance|' /opt/app/config.yml
systemctl restart finance-app
curl http://app-server:8080/health
```

**确认人**：运维

---

### 步骤 8：冒烟测试（00:55）

| 用例 | 预期 |
|---|---|
| 登录 | 成功进入首页 |
| 按日期查询凭证 | 返回结果，条数正确 |
| 录入一张凭证 | 保存成功，可查询 |
| 打开资产负债表 | 数据正确 |
| 查询科目余额 | 数值正确 |

**确认人**：测试 + 业务
**失败处理**：**任一失败即回滚**

---

### 步骤 9：开放访问（01:15）

```bash
curl -X POST http://app-server:8080/admin/maintenance -d "enable=false"
```

## 回滚预案

### 触发条件

- 步骤 4/5/6 任一校验失败，30 分钟内无法定位
- 步骤 8 冒烟测试任一失败，30 分钟内无法修复
- 时间超过 04:00 仍未完成

### 回滚步骤

```bash
# 1. 停应用
systemctl stop finance-app

# 2. 改回 Oracle 连接
sed -i 's|jdbc:mysql.*|jdbc:oracle:thin:@oracle:1521:XE|' /opt/app/config.yml

# 3. 启动
systemctl start finance-app

# 4. 关维护页
curl -X POST http://app-server:8080/admin/maintenance -d "enable=false"

# 5. 处理切换后新增数据（见 sql/03_rollback.sql）
```

**预计耗时**：30 分钟（演练验证）

### 双写保护

切换后 24 小时内保持双写：**Oracle 为主，MySQL 为从**。

这样即使回滚，切换后写入的数据在 Oracle 里也有，不会丢。
